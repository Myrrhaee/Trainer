Основной концепт описан в [achievement-system-v1.md](/Users/ikhudyakov/Cursor-проекты/web/trainer — копия 2/docs/achievement-system-v1.md).

Титулы вынесены отдельно в [titles-v1.md](/Users/ikhudyakov/Cursor-проекты/web/trainer — копия 2/docs/titles-v1.md), потому что титулы — это не обычные достижения, а мета-статусы спортсмена.

## Главный Принцип Каталога

В Achievement System главным объектом является **коллекция**, а не отдельная медаль.

Например:

```text
Коллекция: Серия тренировок
├── Бронза: В ритме
├── Серебро: Не сбавляя темп
├── Золото: Железная привычка
└── Мастер: Годовой ритм
```

Клиент воспринимает это не как четыре разных достижения, а как один развивающийся путь.

## ID Strategy

ID не должен содержать числовой порог.

Плохо:

```text
DISC-STREAK-THRESHOLD-7
DISC-STREAK-THRESHOLD-30
```

Если через год баланс изменится, ID станет неправильным.

Правильно:

```text
DISC-STREAK-BRONZE
DISC-STREAK-SILVER
DISC-STREAK-GOLD
DISC-STREAK-MASTER
```

Числовой порог хранится отдельно в колонке `Порог`.

Так можно менять баланс без миграции идентификаторов.

## Achievement Score

Achievement Score — долгосрочная метрика профиля клиента.

Пример отображения:

```text
1280 Achievement Score
```

Базовая шкала:

| Уровень | Очки |
| --- | ---: |
| Бронза | 10 |
| Серебро | 25 |
| Золото | 50 |
| Мастер | 100 |
| Кубок | 50 |
| Легендарный кубок | 150 |
| Секретное | 25–100 |
| Почётное | 0 или 100 |

Очки не должны превращать продукт в игру ради очков. Это вторичная метрика статуса, а не главная мотивация.

## Прогресс Коллекции

Каждая коллекция должна иметь прогресс.

Пример:

```text
Серия тренировок
██████░░░░
2 / 4 уровня открыто
```

Это делает профиль интереснее: клиент видит не только открытые награды, но и развитие целой коллекции.

## Как Читать Таблицы

| Level ID | Стабильный ID уровня внутри коллекции |
| Категория | Большое направление развития спортсмена |

| Порог | Число или событие, по которому уровень открывается |
| Условие | Человеческое описание условия |
| Score | Очки достижения |
| Версия | MVP, V2 или Later |
| Статус | К согласованию, принято, спорно, отложено |

## Спорные Достижения

Эти достижения требуют отдельного обсуждения, потому что могут поощрять нездоровое поведение, быть слишком сложными для честного измерения или зависеть от будущих функций.

| Level ID | Причина |
| --- | --- |
| DISC-STREAK-MASTER | Может поощрять тренировки без отдыха, если трактовать как календарную серию |
| DISC-NO-MOVES-MASTER | Может превращать гибкость расписания в “штраф” |
| STR-PLANK-LEGENDARY | Слишком специфичный и потенциально странный рубеж |
| FORM-WELLBEING-MASTER | Название “Биохакер” может выбиваться из тона продукта |
| CLUB-ACTIVE-GOLD | Активность каждый день может быть не нужна для премиального сопровождения |
| CLUB-ACTIVE-MASTER | Очень долгий горизонт, лучше оставить на Later |
| CLUB-DATE-NEW-YEAR | Может поощрять тренировку в праздник ради награды |
| CLUB-DATE-HOLIDAYS | Может выглядеть как игровая механика, не спортивная биография |
| COACH-LEGEND-TANDEM | Слишком жёсткое условие без переносов |

## Проверка После Ревизии

Каталог должен проходить такие проверки:

- `Level ID` уникален;
- `Collection ID` стабилен и не зависит от порогов;
- пороги хранятся отдельно;
- названия уровней не дублируются без необходимости;
- одинаковые условия не повторяются в разных категориях;
- титулы не смешиваются с каталогом достижений;
- спорные достижения отмечены отдельно;
- MVP-достижения реализуемы на текущих или ближайших данных продукта.
